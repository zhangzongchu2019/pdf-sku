# Pipeline 设计文档

## 1. 目标

目标是从非约束 PDF 的单页中恢复所有“商品单元”，并为每个商品单元输出：

- 相关文案
- 相关图片
- 可确认的结构化属性
- 字段证据

默认优化方向：

- 页面级高召回
- 字段级禁止臆造
- 允许一定候选噪声
- 允许后续人工筛选

非目标：

- 不追求把所有逻辑都交给大模型
- 不追求依赖页型分支解决问题
- 不追求一次性重写全部旧模块

## 2. 核心定义

### 2.1 商品单元

商品单元不是单张图，也不是单个文本块，而是页面上业务上成立的一组图文集合。

一个商品单元可以包含：

- 一个或多个文本片段
- 一张或多张图片
- 主图、细节图、局部图、变体图

默认拆分原则：

- 是否独立成商品单元，优先看是否存在独立文案
- 同款的主图、细节图、局部图、颜色图默认归入同一商品单元
- 套装若只对应一组主文案、型号或价格，默认归入同一商品单元
- 配件只有在存在独立文案、独立型号或独立价格时，才单独成商品单元
- 无文案页面属于特殊情况，允许仅基于视觉恢复商品单元，但不允许补写文本属性

### 2.2 证据

证据是页面中可被引用的原始信息，包括：

- PDF 原生文本
- OCR 文本
- 图片对象
- 布局区域
- 视觉区域

最终结果应尽量绑定证据，而不是只保留模型结论。

### 2.3 视觉与文本的边界

系统是视觉优先，但不是让 VLM 直接猜属性。

允许：

- 用视觉判断某个商品单元是否存在
- 用视觉判断多张图是否属于同一商品
- 用视觉判断图文是否同属一个宣传单元

不允许：

- 在没有页面证据时补写 `product_name`
- 在没有页面证据时补写 `model_number`
- 在没有页面证据时补写 `price`
- 在没有页面证据时补写 `color/specs`

结论：

- 商品存在判断可以依赖视觉
- 文本属性值必须来自页面证据
- 没有文本证据时，最终结果允许保留商品单元，但文本属性留空

### 2.4 任务拆分

系统应明确拆成两个任务：

- 商品单元识别
- 属性抽取

前者回答：

- 页面里有哪些商品单元
- 哪些图和哪些文案属于同一商品单元

后者回答：

- 该商品单元有哪些可确认属性
- 每个属性的页面证据是什么

## 3. 业务默认判断

### 3.1 页面中有商品描述

如果只有一个商品描述：

- 默认该描述对应本页主要商品图片
- 仍要过滤明显无关宣传图、logo、背景装饰

如果有多个商品描述：

- 主要依赖局部空间关系和整体视觉布局恢复归属
- 不硬依赖“图片下方就是文字”
- 大图旁的小图通常属于同一商品单元

### 3.2 页面中无商品描述

如果多个子图大小相近：

- 默认每个子图是一个独立商品单元
- 即使外观高度相似，默认也拆为多个商品单元
- 第一版不在无文案页面里主动把多个相似图聚合成一个商品单元

如果大小图混排：

- 小图优先视为大图的细节图、局部图或补充视角图
- 主要依据相邻关系、视觉相似度、局部版式单元判断

### 3.3 图片资产

图片处理目标是生成可交付的商品资产，而不是简单裁框。

默认要求：

- 数字版 PDF 优先复用底层原生图片对象
- 若底层图片被切成瓦片，应先合并再判断
- 扫描版页面应从渲染页中恢复商品宣传图，并尽量去除无关背景
- 保留商品主体
- 去除明显多余白边、黑边、背景留白
- 清晰、相对独立、尺寸较大的商品图应尽可能拆开
- 多个很小的示意图、颜色图、规格图可以保留为一整块
- 是否拆分以“是否更好表达商品单元”为准，而不是强制全部细拆

### 3.4 文本提取

文本阶段先求全，再筛选。

原则：

- 尽可能完整提取页面文字
- 再筛出属性信息
- 不一开始就只提结构化字段

重点保留：

- 型号
- 规格
- 颜色
- 价格
- 其他明确属性信息

弱化或丢弃：

- 宣传文案
- 品牌口号
- 与商品属性无关的营销描述

补充原则：

- 识别出的属性相关文本，应优先完整进入“商品描述”
- 结构化字段是在“商品描述”基础上再做抽离
- 不要求一开始就把所有属性都结构化干净

### 3.5 长表格续页

需要兼容长表格跨页场景。

典型情况：

- 首页包含列表头
- 后续页只有列数据
- 后续页本身不再重复字段名称

这类页面不应让后续阶段去“猜字段含义”。

正确做法是：

- 在预处理阶段识别续表关系
- 把首页表头信息继承给后续页
- 让后续页按继承后的列定义解释数据

因此，这里虽然涉及跨页信息传递，但本质上属于“表头继承”，不是开放式跨页语义重构。

当前版本只覆盖简化场景：

- 只认为首页包含表头字段
- 后续页默认不再重复表头
- 这类表格 PDF 默认所有页面都是表格页
- 不处理“中间夹杂纯图页或宣传页”的混合情况

在这个前提下，后续页可以基于首页表头并发处理，而不必逐页重新猜列含义。

## 4. 设计原则

### 4.1 规则层职责

规则层负责：

- PDF 解析
- OCR
- 图片提取
- 页面渲染
- 布局检测
- 切片
- 确定性去重
- 导出和状态管理

规则层不负责：

- 用页型决定主流程
- 用欧式距离直接裁决商品归属
- 用大量特例分支补数据集问题

### 4.2 VLM 职责

VLM 负责：

- 恢复商品单元
- 判断图文归属
- 判断主图与细节图关系
- 从局部证据抽取候选字段
- 页面级验证候选是否应保留、合并、拆分、丢弃

### 4.3 几何关系的地位

几何关系是弱特征，不是硬规则。

可以使用：

- 邻近性
- 对齐关系
- 区域重叠
- 网格结构

但这些只能作为证据的一部分，不能单独决定最终归属。

## 5. 主链路

### Phase 0: 文档级预判

对少量页面做文档级弱预判，只用于：

- 推断文档主题
- 过滤明显无关内容
- 提供弱先验

### Phase 1: 证据采集

采集并标准化：

- PDF 文本
- OCR 文本
- 图片对象
- 页面渲染图
- 布局区域
- 长表格表头与续页关系

输出：`PageEvidence`

### Phase 2: 区域提议

提出候选“商品单元区域”。

目标不是框物体，而是先把可能属于同一商品单元的图文聚到一起。

输出：`RegionProposal[]`

### Phase 3: 区域证据归并

对每个候选区域归并：

- 文本
- OCR 片段
- 图片对象
- 局部截图

输出：`RegionEvidence[]`

### Phase 4: 候选提取

对每个 `RegionEvidence` 做多模态抽取，先识别商品单元，再抽取属性。

输出：`CandidateSKU[]`

### Phase 5: 页面级验证

对全部候选做统一验证：

- 丢弃
- 合并
- 拆分
- 修正归属冲突

输出：`VerifiedSKU[]`

### Phase 6: 规范化与去重

规则层负责字段标准化、型号解析和同页重复合并。

### Phase 7: 绑定与资产生成

先确定商品单元属于哪个区域，再从区域内选主图和细节图。

### Phase 8: 升级与结束

对高风险页面触发有限重入或人工升级。

## 6. 最终输出原则

最终输出以“商品单元”为主，不以区域或图片为主。

每个商品单元应输出：

- 商品单元 ID
- 归属区域
- 相关图片资产
- 商品描述
- 可确认的文本属性
- 字段证据
- `evidence_mode`

如果只有视觉证据：

- 允许输出该商品单元
- 文本属性留空
- `evidence_mode = visual_only`
- 不生成额外视觉描述字段
- 不补写名称、颜色、型号、价格等属性

补充说明：

- 内部语义容器可命名为“商品描述”
- 导出时映射到 Excel 列“商品名称/描述”
